## What this does

`yt_progress_parse` reads STATE.md content on stdin, so the caller can feed a file or `git show` output. It looks at the frontmatter only (up to the closing `---`, or the first `#` heading when the file has no delimiters) for a `progress:` key followed by indented `label`, `done`, `total` and optional `waiting_on`. Values lose surrounding quotes and a trailing ` # comment`; comment lines and unknown keys inside the block are skipped.

Result variables:

- `YT_PROGRESS`: `none` (no block), `ok`, or `bad`
- `YT_PROGRESS_LABEL`, `YT_PROGRESS_DONE`, `YT_PROGRESS_TOTAL`, `YT_PROGRESS_WAITING`: set only when `ok`
- `YT_PROGRESS_ERRORS`: one line per problem when `bad`

Rules for `ok`: `label` present and at most 16 characters; `done` and `total` are plain digits (at most 9); `total >= 1`; `done <= total`. `progress:` with an inline value is `bad`.

`yt_state_lint` calls the parser on `STATE.md` and adds one warning per error line (W7). No block means no warning.
