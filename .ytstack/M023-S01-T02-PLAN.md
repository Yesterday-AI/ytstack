## What this does

`bin/ytstack-brief render --task M###-S##-T##` or `--slice M###-S##` prints one Markdown brief on stdout. It is built from the plan files: outcome, scope (the Files sections), what to read, verification, spec impact, gates and, with `--branch`, the checkout command. The work contract is the body of `skills/minimal-code/SKILL.md`, read at render time, so the text lives in one file. "Read for context" names the plan files, `spec/SPEC.md` and the area files of the planned paths. A slice brief names a task without a plan as not planned. Without a plan, a `## Files` section, the template or the contract the script prints no brief and exits 1.

`bin/ytstack-brief check` reads a worker's report from a file or from stdin. It prints `report ok` when the eight labels are present, each with a value, and every `Checks run:` line carries an exit code or says `none` with a reason. Otherwise it prints one line per problem and exits 1.

`brief-template.md` holds the skeleton, the fixed sentences and the report shape. The script fills its markers and leaves out a section whose marker has no value (Gates, Git). The same file serves an orchestrator that has to fill a brief by hand.
