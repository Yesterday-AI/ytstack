## What this does

`register` refuses a PR another session owns, so a coordinator that rotates to a fresh session today loses its watches: the successor's `register --all-open` skips all of them by name. `handover` moves, in one transaction:

- every watch of `--from` to `--to`;
- the notices of `--from` that are not delivered, not cancelled and not in flight to Codex (no `dispatch_id`), so they reach the successor;
- the branch bindings and candidates of `--from` (a PR opened later on a lane's branch is adopted for the successor);
- and it writes `handover:<from>` = `<to>` into `meta`. `register` follows that pointer (to its end, cycle-safe), so a PR a still-running subagent of the old session opens after the handover is registered to the successor. A handover to a session clears that session's own pointer, so handing back works. The successor's `surface:` fingerprint is reset so its next prompt shows the block.

`--to` defaults to the current session like `register --session`. A bare id equal to the current Claude session is qualified. `--from` equal to `--to` is a usage error. The output names the moved PRs and the counts; a session with nothing to move still gets the forward and exit 0.
