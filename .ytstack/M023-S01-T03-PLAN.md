## What this does

`spawn-milestone-team` no longer carries a hand-written brief. Step 5 runs `bin/ytstack-brief render --slice ... --branch ... --base ...` for every open slice and uses the output as the Agent prompt, plus two lines the plans do not hold. Slices go out by dependency: independent ones in one message, a dependent one after its base is verified. Step 6 runs `bin/ytstack-brief check` on the worker's report before anything is done with it. An incomplete report goes back once with the checker's lines, and the orchestrator does not fill the gap itself. A second incomplete report stops that slice, and a blocker goes to the user once.

Step 7 hands the verifier the worker's eight report lines. After a fix, the next verifier gets the earlier verdict and runs again only the checks of tasks whose files changed since that commit.

The implementer reports in the shape the brief gives and takes the contract in the brief as the measure for code and checking. The architect names a concrete case per finding and adds no acceptance condition the plan does not have. `codex/adapter.md` tells a Codex session that a prompt starting with `# Brief:` is complete in itself, and names the command that starts a Codex worker with it. `docs/codex.md` lists the same as a support row, marked as not exercised in a live run.
