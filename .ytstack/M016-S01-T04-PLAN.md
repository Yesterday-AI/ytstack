# M016-S01-T04 -- Task Plan

**Summary:** Rewrite `hooks/post-tool-use-bash` so the draft-summary stub is created only in the checkout where the commit happened (payload `cwd`), only when the HEAD subject carries the active task's commit ref, and so wrapper tokens such as `rtk`/`sudo`/`env` before `git commit` are recognised.

## Files

- Modify: `hooks/post-tool-use-bash` (full rewrite, ~90 lines)
- Modify: `tests/post-tool-use-bash.test.sh` (payload carries `cwd`; fixtures use task-ref subjects; 5 new cases)

## What this does

```
. lib/git-ctx.sh; yt_read_stdin
exit 0 unless YT_TOOL_EXIT is empty or 0
matcher (bash ERE): (^|[;&|()])[[:space:]]*((rtk|sudo|command|env([[:space:]]+[A-Za-z_][A-Za-z0-9_]*=[^[:space:]]*)*)[[:space:]]+)*git[[:space:]]+commit([[:space:]]|$)
  -> still rejects `echo "git commit"` and `git log | grep commit`; accepts `rtk git commit`, `sudo git commit`, `env X=1 git commit`
yt_git_ctx "${YT_CWD:-$PWD}"; exit 0 unless YT_IS_GIT=yes
YT_DIR=$(yt_resolve_yt_dir) || exit 0          # the committing checkout's own .ytstack, never CLAUDE_PROJECT_DIR
STATE -> CURRENT_MILESTONE / ACTIVE_SLICE / ACTIVE_TASK; exit 0 when task none
PATTERN = commit_ref_pattern from "$YT_DIR/PREFERENCES.md" (frontmatter or `key: value` line), default '^M###-S##-T##:'
  tokens: M### -> $CURRENT_MILESTONE, S## -> $ACTIVE_SLICE, T## -> $ACTIVE_TASK, {task} -> M-S-T ref
SUBJECT = git -C "$YT_TOPLEVEL" log -1 --pretty=%s; exit 0 unless [[ $SUBJECT =~ $PATTERN ]]
SUMMARY_FILE="$YT_DIR/$M-$S-$T-SUMMARY.md"; exit 0 if it exists (stub-once, unchanged from M015)
write the draft stub (same template as today, plus `worktree:` in frontmatter)
```

Known limitation (documented in the hook header): a command that `cd`s elsewhere before committing is attributed to the payload `cwd`; the stub then lands in that checkout's `.ytstack` or nowhere. Acceptable: `summarize-task` owns the durable commit list.

Test changes (`tests/post-tool-use-bash.test.sh`):
- `fire` sends `{"cwd": <repo>, "tool_input": {...}, "tool_response": {"exit_code": N}}` from a neutral cwd with `CLAUDE_PROJECT_DIR` pointed at a bogus dir.
- Fixture commits that must stub use subjects `M999-S01-T01: ...`.
- Existing T1-T9 keep their intent (T1 stub once, T2 no re-write, T3/T4/T9 matcher negatives, T5 failed commit, T6 settles, T7 no active task, T8 chained).
- New: T10 commit in a linked worktree with `CLAUDE_PROJECT_DIR`=main -> stub in the worktree's `.ytstack`, main `git status` clean. T11 commit without the task ref -> no stub. T12 `rtk git commit` -> stub. T13 `PREFERENCES.md` with `commit_ref_pattern: ^feat\({task}\)` and a matching subject -> stub; non-matching -> none. T14 payload without `cwd`, hook run from the repo dir -> falls back to `$PWD`, stub created there.
