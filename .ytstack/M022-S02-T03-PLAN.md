## What this does

The `code-review` preamble prints `SPEC_EXISTS` and, between `SPEC_AREAS_BEGIN` and `SPEC_AREAS_END`, the area files that cover the files changed in `BASE_SHA..HEAD`. When a spec exists, the reviewer gets the plan's `## Spec impact` and those area files with its requirements and reads them, and the section of a source they point to, against the diff. Two things are findings: the diff changes something an area file describes while the plan says `none`, or an area file or its source now states something the diff contradicts. A change that restores the described behaviour is not a finding. The reviewer does not audit other areas or the rest of the documentation.

A reversal of an earlier choice goes to `DECISIONS.md`, and the area file it concerns lists the new entry under "Decisions that apply now" instead of the old one.

The verifier's step 6 confirms from the task's commits that each area the plan names, or a path under its `sources`, changed, and reads the changed section against what the task did. For a plan that says `none` it reads the area file that covers the changed files and checks that no statement in it is now false. A named area without a change, or a statement the task made false, is a FAIL with the file and the sentence.
