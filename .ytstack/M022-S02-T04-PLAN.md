## What this does

The `reassess-roadmap` preamble prints the output of `bin/ytstack-spec drift` between `SPEC_DRIFT_BEGIN` and `SPEC_DRIFT_END`. Step 3a answers each `possible documentation impact` line once per area for the whole slice: the area file is read against the commits the line counts. A statement that became false is corrected in the area file or its source. When nothing became false, `verified_at` is set to the commit that was checked. No description is edited to quiet the report, and slice closure never waits on this step.

`resume-session` reads only the "Areas" table of `spec/SPEC.md`, names the area file of the work that is next and does not restate it. Without a spec it points at `adopt-brownfield`. `handoff-session` replaces a description of behaviour or scope with the path that holds it, and its template names `spec/SPEC.md`. When `spec/SPEC.md` exists, the closing sentence of the SessionStart state block reads "Read STATE.md for the full dashboard, spec/SPEC.md for what applies now, DECISIONS.md ...".
