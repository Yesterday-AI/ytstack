## What this does

ytstack describes itself in six areas: `skills`, `artifacts`, `hooks-and-state`, `host-adapters`, `dependencies`, `checks-and-evals`. Each area file is `status: implemented` with `verified_at: f4f54ab`, names its `paths` and, where a document already holds the description, its `sources`. `SPEC.md` lists the six areas, the invariants that hold everywhere, the four check commands and the "Keeping this true" block.

`check_spec` in `bin/ytstack-check` runs `bin/ytstack-spec lint` and `drift` on the plugin root. A format error is a `[fail]`, a drift line is a `[warn]`. It is skipped when the tree has no `.ytstack/spec/`. `check_keeping_block` fails when the "Keeping this true" bullets in `skills/init-project/SKILL.md` or `skills/adopt-brownfield/SKILL.md` differ from `docs/ux/spec-format.md`.

The test block covers four cases: a tree without a spec yields no spec finding, a well-formed spec yields none, a section outside the fixed list is a `[fail]` with exit 1, and a drifted copy of the maintenance block is a `[fail]`.
