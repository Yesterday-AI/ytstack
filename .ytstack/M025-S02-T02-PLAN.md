## What this does

`bin/ytstack-risk floor --base <sha> --head <sha>` reads the tree difference between two commits and prints the lowest class the change can have: `floor: low`, `floor: normal` or `floor: person`, one `reason:` line per rule that raised it, then `areas:` and `ceiling:`.

The policy is read at the base commit, never from the working tree: the `paths` and `auto_merge` of the area files, `REVIEW.md` and `evidence_dir`. A change to any of them is itself `person`, so a change cannot relax the route it takes.

`person` rules: the rule documents, an instruction file at any depth, the checks, the frontmatter and the two rule sections of an area file, the invariants section of `SPEC.md`, a file of the spec that was added or deleted, a path no area covers (process records are exempt), and the project's "Always a person" list. `normal` rules: the built-in list `NEVER_LOW`, the project's "Never low" list, and the size limit. Globs are matched by git itself (`:(glob)` pathspecs over the diff), the same semantics `lint` and `drift` use for `paths`.

`bin/ytstack-risk check` validates the `REVIEW.md` of the working tree and prints one line per problem. `bin/ytstack-spec lint` runs it when `REVIEW.md` exists and counts each line as a failure.
