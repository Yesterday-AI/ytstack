## What this does

`plan-task` works out the spec impact itself; it does not ask the user. Without `spec/SPEC.md` the impact is `none -- the project has no technical spec`. Otherwise the skill runs `ytstack-spec areas` on the files of Step 4, reads the area file of each hit and the section of a source it names, and nothing else of the spec. A task that changes behaviour, an interface, an invariant, an error path, a limit or where the area is implemented gets one line `- <area>: <section> -- <what changes>`. A fix that restores the description and a change without behaviour get no line; with no line at all the plan says `none -- <reason>`. A change that is not trivial in a file without an area is named in the report; the skill creates no area file.

The plan template has `## Spec impact` between "What this does" and "Verification". With `granularity: slice` the section goes into the slice plan. `quick-task` corrects a statement in an area file or its source only when the quick change made it false, in the same commits.

## Spec impact

- artifacts: Behavior -- a task plan has a `## Spec impact` section that `plan-task` works out from the area files
- skills: Behavior -- `plan-task` determines the spec impact; `quick-task` corrects an area file only when its change made a statement false
