## What this does

The initial adapter maps `ytstack:<name>` to Kimi's qualified Skill invocation and maps each ytstack gstack wrapper to the original bare gstack skill. It documents independent discovery of the existing pinned gstack installation. A bare name never denotes an ytstack plugin skill, which prevents same-name recursion.

The Python suite first goes RED against the missing native files. It then verifies the package contract in an installed path containing spaces and compares the exposed skills with the existing `skills/` tree. A separate temporary gstack fixture contains the six same-name skills and the pinned VERSION. Each real ytstack gstack-wrapper preamble runs against that fixture through `GSTACK_HOME`, proving independent discovery without copying anything into the plugin. The tests do not assert on adapter prose or simulate Kimi's resolver. These are packaging tests, not a claim of live Kimi model invocation; S01-T02 performs the fresh CLI verification of qualified ytstack skills and bare gstack invocation.

Add an explicit Kimi unittest discovery step to the existing plugin-check workflow. Leave unrelated host work and existing Claude Code/Codex contracts untouched.
