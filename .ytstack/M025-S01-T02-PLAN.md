## What this does

The `RUNTIME.md` that `init-project` writes gains the headings "Run", "Release" and "Signals", each with one line of free text and no key line. Such a file passes `bin/ytstack-runtime check` untouched, because a section without a list line counts as absent. `adopt-brownfield` writes the same three headings. It writes a key line only when a document or a script of the project states the command, and the free-text line of the section names that source. It never invents a command.

`plan-task` says in its verification step: a task whose result shows only at the running product names `Environment: instance from bin/ytstack-runtime up` and what is checked there.

`verification-before-completion` prints in its preamble where the script is and whether `RUNTIME.md` has a "Run" section. Its ytstack paragraph says: when the plan names a running instance, start it with `up`, check there, note the `COMMIT:` line with the output, stop it with `down`. Without a "Run" section, or when `up` fails, the check at the running product was not possible; that is reported and never claimed. The implementer and the verifier get the same rule in one line each.

The suite of the script takes the `RUNTIME.md` template out of both skills and runs `check` on it. The preamble suite pins the two new preamble lines.
