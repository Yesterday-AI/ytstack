# M017-S01-T02 -- Task Plan

**Summary:** Guard the inlined superpowers text against namespace and relative-link leaks: the three superpowers wrappers get a "Namespace note" postamble that translates `superpowers:<skill>` to `ytstack:<skill>` and anchors relative `.md` links to the vendor skill dir; `bin/ytstack-check` fails when a wrapper inlines vendor text with such leaks and lacks the note.

## Files

- Modify: `skills/test-driven-development/SKILL.md`, `skills/systematic-debugging/SKILL.md`, `skills/verification-before-completion/SKILL.md` (postamble after the inlined block)
- Modify: `bin/ytstack-check` (new check `check_inline_leaks` in the resolver-contract section)
- Modify: `tests/ytstack-check.test.sh` (fixture wrapper + fake vendor skill with both leak kinds)

## What this does

Postamble (verbatim in each of the three wrappers, after the ```!cat ...``` block):

```markdown
## Namespace note (ytstack)

The text above is upstream superpowers content rendered inside ytstack. Read `superpowers:<skill>` as `ytstack:<skill>` (e.g. `superpowers:verification-before-completion` is `ytstack:verification-before-completion`); invoke the ytstack-namespaced skill via the Skill tool. Relative links such as `writing-good-tests.md` resolve under `vendor/superpowers/skills/<skill>/` in the ytstack plugin directory (`${CLAUDE_SKILL_DIR}/../../vendor/superpowers/skills/<skill>/`).
```

Checker (`check_inline_leaks(root)`): for each wrapper that inlines `vendor/<x>/.../SKILL.md` (regex as in `check_vendor_sibling_refs`), read the vendor text; collect `superpowers:[a-z0-9-]+` tokens and relative markdown links `\]\(([A-Za-z0-9_./-]+\.md)\)` that are not URLs/absolute; FAIL `"<wrapper>: inlined vendor text references `superpowers:X` but the wrapper has no Namespace note translating it"` unless the wrapper contains `## Namespace note` and the literal token; FAIL for relative links unless the wrapper contains `## Namespace note` and the phrase `resolve under`. Only wrappers under `skills/` are scanned; vendor files themselves are never edited.

Test additions in `tests/ytstack-check.test.sh` (copied tree): write `vendor/superpowers/skills/zz-fake/SKILL.md` containing `superpowers:zz-other` and `[x](notes.md)`, and a wrapper `skills/zz-fixture-wrapper/SKILL.md` that cat-inlines it without a note -> 2 fails naming both leaks; add the Namespace note with the token -> 0 fails from this rule. (The copied tree already symlinks `vendor/`; create the fake vendor skill in a copied `vendor/superpowers/skills` dir instead -- adjust the copy step to `cp -R` only `vendor/superpowers/skills/zz-fake` into a real dir layered over the symlink? Simplest: replace the vendor symlink by `mkdir -p $ROOT/vendor/superpowers/skills` + symlink the three real wrapped skill dirs individually + the fake dir as a real dir.)
