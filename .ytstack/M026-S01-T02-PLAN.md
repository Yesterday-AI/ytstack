## What this does

After a merge somebody watches whether the target serves the commit and stays healthy, and it is not the person.

`finish-lane` gets the step "Watch the release" after "Merge or hand over". It runs after a merge by anyone: the session's own, or a person's when the skill is called again for a lane whose pull request has merged. It reads the merge commit of the pull request from the host and starts `bin/ytstack-watch release --commit <merge commit>` (`docs/ux/runtime-format.md`, "Release"). The five lines of the receipt go into the lane's report unchanged. `not arrived` and `unhealthy` go to the person at once. Without a "Release" section the report says in one line that the release was not watched and why. The skill deploys nothing, restarts nothing and rolls nothing back; a countermeasure on the target is a step for a person.

`coordinate` names the watch where it acts on a pull request that merged.

`bin/ytstack-watch release` is built in M026-S01-T01 by another worker. This task names its command line, its exit codes and its receipt as that worker's report states them.
