## What this does

`signal-intake` is a native procedure skill for a run nobody watches and for a person who asks what production reports. It asks nothing, so it behaves the same with and without `YTSTACK_NON_INTERACTIVE`.

The preamble prints the sources (`bin/ytstack-runtime signals`), the result of `bin/ytstack-runtime check` and every existing finding. A project without `.ytstack/`, without the scripts or without a "Signals" section stops the skill; for the missing section it prints the lines to add and guesses no command. Each source is read once by one shell block that stamps the read time, the exit code and the line count and keeps the output outside the checkout. A source that printed nothing and failed counts as not read and is recorded as a finding of its own, so that a broken source is not silence.

The skill states how a key is chosen (the source name, a colon, the identity at the source; an existing finding keeps its key) and seven rules, first match wins, that separate a finding from noise. It never sets a threshold: a performance line without the verdict of its source is counted as not judged. Findings go through `bin/ytstack-signals new` with the read time of their source; for a new finding and a regression the skill writes "Assessment" and "Next". It ends with one report: per source the read time and line count, new findings, regressions, findings seen again, dismissed ones seen again, noise by rule, what was not judged and what could not be read.

It never opens a task, edits a product file, fixes, dismisses or marks a finding fixed. The Terminal State names what happens next and who does it.

The eval case builds a project whose two sources are scripts that print fixed lines: one new error, one that an open finding already carries, one that a fixed finding carries. Its graders are free ones.
