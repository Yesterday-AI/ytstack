## What this does

```
yt_ensure_gitignore <toplevel>
  block = "# ytstack local state (fallback session dir; see hooks/lib/git-ctx.sh)\n.ytstack/.local/"
  if <toplevel>/.gitignore contains the line ".ytstack/.local/" -> no-op, YT_GITIGNORE=unchanged
  else append the block (preceded by a newline when the file does not end with one), YT_GITIGNORE=written
  never ignores .ytstack/HANDOFF.md or .ytstack/journal/ (those are user-owned / retired)
```

`init-project`:
- Checklist 6 and the process-flow node become "Write `.gitignore` block"; Step 6 runs `yt_ensure_gitignore "$_PROJECT_DIR"` (lib loaded by the preamble) and reports `GITIGNORE: written|unchanged`; for `user`-only scope it is skipped (nothing in-tree).
- `PROJECT.md` template frontmatter gains `init_completed: {ISO_TIMESTAMP}` and `scope: {SCOPE_CHOICE}`; the scope re-ask hint becomes "(to re-ask later: change `scope:` in PROJECT.md and re-run)".
- No `touch ~/.ytstack/...` lines remain anywhere in `skills/`.

Tests (append to `tests/git-ctx.test.sh`): fresh repo without `.gitignore` -> file created with the block; existing `.gitignore` lacking a trailing newline -> block appended on its own line, original content intact; second call -> `unchanged`, exactly one `.ytstack/.local/` line; a `.gitignore` that already lists `.ytstack/.local/` in another form (e.g. `.ytstack/.local`) is left alone only if the exact line is present, otherwise appended (documented behaviour); `HANDOFF.md` not ignored. Static: `grep -rn '~/.ytstack/\.' skills/` is empty.
