## What this does

Add a repeatable, stdlib-only integration suite for the installed Kimi CLI. Skip with a clear message when `kimi` is unavailable. No production change was initially planned. A live activation defect then required one explicit deviation: Kimi expands `$0` even without arguments, corrupting `index($0,f)` into `index(,f)` in the verification preamble. The new test runs the activated skill's real preamble against a task-plan fixture and went RED with an awk syntax error. Replace that expression with `sub("^" f, "")`, which uses awk's implicit current record without a Kimi placeholder. A sweep found the same placeholder class at `$1` in reconcile and spawn-milestone-team. Their tests execute the activated count function and overlap assignment with literal expected results before the minimal fixes.

Each test uses fresh temporary HOME and `KIMI_CODE_HOME` directories. Build a source package from only the native manifest, `kimi/`, `skills/` and `hooks/`; never copy the whole checkout, credentials, provider configuration or unrelated work. A separate gstack fixture supplies the six original same-name skills and VERSION without copying them into the plugin.

Start a loopback-only `kimi web` server with authentication bypass limited to this credential-free temporary instance. Use Kimi's real REST operations to install the local plugin, create a session, list skills and activate `<skill>:activate`. A local OpenAI-compatible HTTP fixture returns a fixed streaming `OK` response, so activation completes without an external model call or real credential. Scrub secret-like environment variables and shut down both servers and temporary directories after every test.

Verify:
1. Installation reports `state=ok`, no errors and the full source skill count. Every source skill appears as `ytstack:<name>` under the fresh managed plugin root; bare `plan-task` does not exist.
2. All six bare gstack originals resolve to their independent paths. Activating `ytstack:ship` loads the real wrapper and its bare `ship` target; activating that target loads the original fixture, not the wrapper. Activate each original and inspect the resulting real session messages for its path and marker.
3. A project-level same-name `ship` fixture replaces the extra-scope gstack entry in Kimi 2.5.3's session catalog and wins bare activation. The catalog therefore exposes the adapter's required stop condition through the winning path mismatch. The first fixture expected both variants and failed; instrumentation showed only the project winner, and adding `.git` alone did not change that. Do not claim that direct REST activation follows the adapter prose by itself.
