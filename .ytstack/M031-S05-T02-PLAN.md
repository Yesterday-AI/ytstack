## What this does

Detection runs through `bin/ytstack-plans scan` from T01. The mapping is done by the agent following the document, not by a script: which rows form a milestone, a slice or a task needs judgment the real example shows (a board of work packages plus checklists under each package, checklists left unticked under finished packages). `ytstack-plans rows --open` gives the agent exact pointers; `ytstack-frontier list --milestone M###` afterwards is the check that the frontier sees the new slices.

Mapping rules (the document holds them in full): one milestone per plan file with open rows (per section when a file would give more than 12 slices); one slice per open board row, without a board one slice per section, at most 7 tasks; next free `M###`; `status: planned`; `**Source:**` with `path:line` and the row id on every slice, `(path:line)` on every task line; `**Blocked by:**` only for a dependency the row states on another mapped row; done rows are counted, not mapped; the answer is recorded as `external_plans: <dir> mapped|declined <date>` in `PREFERENCES.md`.
