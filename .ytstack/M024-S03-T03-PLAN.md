## What this does

In a project that keeps `.ytstack/questions/`, each gate that needs a person's verdict is carried as one question file, so that it survives the session and is not asked twice. Before the one question of Step 3b goes out, `reassess-roadmap` writes a file for a gate that has none with `bin/ytstack-questions new --question ... --decides ... --blocks <gate id>` and fills its Context, Options and Recommendation.

A gate whose file is already `asked` is listed as waiting since that time and is not put again unless something changed. When the question goes out, each file in it is marked with `ytstack-questions ask <id>`. When the human answers, the answer is written under `## Answer`, then `ytstack-questions answer <id>` runs, then the gate line is changed as before.

A project without the directory skips the paragraph: the gate lines alone carry the state. The slice boundary stays the place where all open gates go out in one message.
