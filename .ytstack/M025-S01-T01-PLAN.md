## What this does

`bin/ytstack-runtime` reads the three fixed sections "Run", "Release" and "Signals" of `RUNTIME.md` in the resolved `.ytstack` directory. Every other script and skill reads the file through it.

`get <section> <key>` prints one value of "Run" or "Release" and exits 1 when the section or the key is missing. `signals` prints one tab separated line per source. `check` names each defect of the three sections: a malformed list line, an unknown key, a key twice, "Run" without `start` or `ready`, `{port}` without `ports`, a `ports` value that is no range, "Release" without `deployed`, a `settle` that is no number, a signal without `read` or `kind`, a `kind` outside the four values, a name twice, a token-looking string.

`up [--timeout <seconds>]` starts the product in the background on a free port of the `ports` range, waits for `ready` and prints `URL:`, `PORT:`, `PID:`, `LOG:` and `COMMIT:`. The start position in the range comes from the worktree key, so two worktrees get different ports; a port somebody else holds is skipped. The state (pid, port, log) lives outside the checkout, in the per-worktree state directory of `hooks/lib/git-ctx.sh`. A second `up` prints the running instance. A start command that exits, and a `ready` that never passes, end with the last lines of the log and exit 1, with nothing left running. `down` ends the process group that `up` started, after the `stop` command when one is set. `status` prints the instance or `not running`.
