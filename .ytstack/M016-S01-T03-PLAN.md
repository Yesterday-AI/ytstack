## What this does

```
. lib/git-ctx.sh; yt_read_stdin; yt_git_ctx "${YT_CWD:-$PWD}"; YT_DIR=$(yt_resolve_yt_dir) || exit 0
read project/current_milestone/active_slice/active_task from STATE.md (sed, no git)
REASON from payload `.reason` (clear|logout|prompt_input_exit|other; via the already-parsed YT_STDIN + jq if present, else "unknown")
escape the few string fields for JSON (backslash, double quote, control chars -> sed) and printf ONE line:
  {"timestamp":..,"event":"session-end","reason":..,"session_id":..,"project":..,"milestone":..,"slice":..,"task":..,"worktree":..,"linked_worktree":..}
  >> "$(yt_state_dir)/session.jsonl"
exit 0 always; never create .ytstack/journal/, never touch any file under YT_DIR
```

Single-writer by construction: the file lives in `sessions/<session_id>/`, so concurrent sessions never share a file (no `flock`, absent on macOS). `yt_git_ctx` is the only git usage (4 short `rev-parse` calls) and is required to find the right checkout.

Test (`tests/session-end.test.sh`):
1. Main checkout: one valid JSON line (`jq -e .`) in `<pd>/repos/<k>/worktrees/<w>/sessions/s1/session.jsonl` with `session_id`, `milestone` from STATE, `reason` from payload; `.ytstack/journal/` not created; `git status` clean; `CLAUDE_PROJECT_DIR` pointed elsewhere and ignored.
2. Same session fired twice -> two lines, same file (append semantics).
3. Linked worktree payload -> line under the worktree key, `worktree` field = worktree path, main `git status` clean.
4. Two sessions -> two files, one line each.
5. Repo without `.ytstack` -> exit 0, no files.
6. STATE values with a double quote and a backslash are escaped (still valid JSON).
7. No stdin -> `session_id` `nosession`, `reason` `unknown`, still out-of-tree.
8. Budget: 5 consecutive invocations complete in under 2.5 s wall time (python3 timer; generous CI margin for a 1.5 s per-call budget).
