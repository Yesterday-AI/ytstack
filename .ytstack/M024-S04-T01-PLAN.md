## What this does

`coordinate` is the skill for the session that owns a plan and delegates all of it. It edits `.ytstack/` and pull request bodies and nothing else: no product code, no review of a diff, no statement about a pull request that was not read from the host for that statement.

Its preamble prints the rows of `LANES.md`, the frontier, the open and asked question files, whether `STANDING.md` exists and the times of the two handoffs. The procedure is one loop. It starts from those files at the first start and after every compaction or resume. It reads host facts fresh with `ytstack-watch --once` and carries their read time. It claims a ready lane, renders the brief, dispatches and checks the report. It finishes reported lanes through `finish-lane`, asks one question at a time from a question file, writes a standing instruction into `STANDING.md` when it is given, and stops a lane that failed verification twice or would need a third review. After one compaction it rotates: files current, a handoff, a fresh session.

`bin/ytstack-watch --pr <numbers>` polls pull requests through `gh` outside the model. Per pull request it reads state, head, checks, the newest review with its commit, and mergeability. The first poll prints every pull request; after that a line appears only when one of the five values changed. `--once` prints one line per pull request with `read <UTC>` and exits. The loop ends when every watched pull request is merged or closed. Nothing is written into the repository.
