## What this does

The wrapper `systematic-debugging` says what to do with a test that fails only sometimes, before the vendored procedure starts. The test is not rerun until green and not skipped. The reproduction rate is raised first: in a loop, alone and inside the full suite, with the same seed and a changed one, with randomness, clock and order pinned. Then the same test runs on the base commit. A flake that is there too is not this change's defect: it becomes a tracked follow-up with its rate and conditions, and the required check on the current commit still has to turn green. A test that fails only with the change is a defect of the change. Where the vendored text and the paragraph differ, the paragraph applies.

`handoff-session` picks the one or two ytstack skills the next session should start with, from the next action, and writes them into a "Suggested skills" section of `HANDOFF.md`, one line each with half a sentence why.
