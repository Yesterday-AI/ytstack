## What this does

`bin/ytstack-finish-lane` holds the steps between a worker's report and a merge at the reviewed commit, one step per call. Every step prints what it did or what it read and refuses instead of assuming. The host is GitHub through `gh` and nothing else. Nothing is written into `.ytstack/`.

`leftovers` sorts what the worker left uncommitted into in scope, out of scope and junk. `commit` stages the in-scope files by name and refuses while junk, out-of-scope files or unmerged paths exist. `push` sends the branch to origin and cannot overwrite the remote. `open-pr` prints the number of the pull request it opened. `wait-head` passes when the host shows the local tip as the head. `body-check` lists backticked paths of the body that are not at the head, with "removed by the diff" when the base still had them.

`gates` reads the host at the moment of the call and prints one line per gate and the UTC time of the read: the head is the reviewed commit, the checks passed, no review on the head requests changes, no review thread is unresolved, the pull request is open and without a conflict, and with `--max-open` the cap on open pull requests holds. `merge` runs the gates for `--at <sha>`, merges only when all hold, pinned to that commit on the host's side, and reads the state back.

The suite runs against a stand-in for `gh` that answers from fixture files and logs its arguments, and a local bare repository as origin.
