## What this does

Implement a thin Bash helper rooted at its own installed location. `skill <name>` mirrors the existing Codex environment contract and runs blocks from the target project. `hook <event>` accepts only the five lifecycle events and never treats the plugin process cwd as the project cwd.

SessionStart and PostCompact invoke shared `hooks/session-start` with T01's plain mode and the Kimi adapter, then atomically write `pending-context.md` under the existing out-of-tree per-session state directory. UserPromptSubmit atomically moves that file aside, emits it as plain stdout and removes it; parallel calls can consume it at most once. No pending file means no output. PreCompact delegates the existing handoff and discards guidance that Kimi ignores. SessionEnd delegates the existing journal.

Register SessionStart (`startup|resume`), PreCompact/PostCompact (`manual|auto`), UserPromptSubmit and SessionEnd (`exit|archive`) directly in the native manifest with quoted `${KIMI_PLUGIN_ROOT}` commands and bounded timeouts.

Extend the executable lifecycle suite for helper skill paths, prepare/consume, no-pending silence, PostCompact rearm, parallel consume-once, handoff, journal and manifest registration. Tests run the helper with cwd set to the plugin root and the project only in stdin, proving payload-based target resolution. CI runs this suite.

Update the adapter: when Kimi's Skill tool accepts `path`, invoke original gstack with both `skill=<name>` and `path=<GSTACK_DIR>/<name>/SKILL.md`; otherwise use the existing bare-name source check and stop on a mismatch. Document the pending lifecycle without claiming SessionStart stdout injection.
