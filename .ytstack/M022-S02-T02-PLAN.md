## What this does

The preamble runs `bin/ytstack-spec impact` with the plan file and the task's commit pattern when the project has a spec, the plan exists and the script is reachable. It prints `HAS_SPEC`, `SPEC_IMPACT_EXIT` and the tool's lines between `SPEC_IMPACT_BEGIN` and `SPEC_IMPACT_END`.

Step 8 reads that result. Exit 0: the plan says `none`, or the area file or one of its `sources` changed with the task; the printed lines become the spec record. Exit 1: the skill stops and writes no summary. The two ways forward are to update the area file or its source, or to correct the plan to `none -- <reason>` and record that under Deviations. Exit 3: the plan was written before the section existed, and the impact is decided now by the rule of `plan-task` Step 7. Without a spec the record is `none -- the project has no technical spec`; when the script is not reachable the check is done by hand from `git log --name-only`.

The summary template has `## Spec` between "Follow-ups" and "Verification". A sentence in the summary does not satisfy the check.
