## What this does

`route` takes `--pr N` and optionally `--repo OWNER/NAME` (default: the repository `gh` resolves from the checkout). With `--pr`, `--plan` is optional. The script reads `repos/<repo>/pulls/<N>/reviews` once through `gh api --paginate`, keeps the reviews that are neither pending nor dismissed and whose `author_association` is `OWNER`, `MEMBER` or `COLLABORATOR`, and takes from their bodies every line that starts with `- Round <n>:` or `- Lens <name>:`, in the order the reviews were submitted.

For the round and for each required lens the newest line on the host counts. When no review carries one, the plan's newest line counts, as before. The line of a host review must name the commit the host tied the review to (`commit_id`); a line that names another commit is ambiguous and routes to a person. The validity for the head is computed from `commit_id`, with the same rule as before (only process records changed since). A review in the state `CHANGES_REQUESTED` routes to a person whatever its line says. A read that fails routes to a person with the reason. With `--pr` the output has one more line, `round: host review <id> by <login> on <commit>`, `round: plan` or `round: none`.

The tests use a stand-in `gh` that answers from a JSON fixture with the fields of the GitHub reviews API and applies the script's `--jq` filter with `jq`.
