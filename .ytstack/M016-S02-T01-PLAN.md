## What this does

Every preamble starts with the same block (written once here, pasted verbatim; `bin/ytstack-check` S02-T05 will later enforce the banned patterns):

```bash
# ytstack resolver (M016): checkout = where this shell runs, via the shared lib.
_LIB="${CLAUDE_SKILL_DIR}/../../hooks/lib/git-ctx.sh"
if [ -f "$_LIB" ]; then
  . "$_LIB"; yt_git_ctx "$PWD"; yt_resolve_yt_dir >/dev/null
  _PROJECT_DIR="$YT_TOPLEVEL"; _YT_DIR="$YT_DIR"; _YT_SCOPE="$YT_SCOPE"; _IS_GIT="$YT_IS_GIT"; _PROJECT_KEY="$YT_REPO_KEY"
else
  # Host did not substitute CLAUDE_SKILL_DIR (e.g. Codex adapter): project scope only.
  _IS_GIT=$([ "$(git rev-parse --is-inside-work-tree 2>/dev/null)" = true ] && echo yes || echo no)
  _PROJECT_DIR=$(git rev-parse --show-toplevel 2>/dev/null || pwd -P)
  _YT_DIR=""; _YT_SCOPE=none; _PROJECT_KEY=""
  [ -d "$_PROJECT_DIR/.ytstack" ] && { _YT_DIR="$_PROJECT_DIR/.ytstack"; _YT_SCOPE=project; }
fi
cd "$_PROJECT_DIR" 2>/dev/null || true
_PROJECT_SLUG=$(basename "$_PROJECT_DIR")   # display only
_HAS_YTSTACK=$([ -n "$_YT_DIR" ] && echo yes || echo no)
```

`${CLAUDE_SKILL_DIR}` is substituted by Claude Code when the skill is loaded (skills live at `skills/<name>/`, the lib at `hooks/lib/`). The `!`-block wrappers use the same block but keep echoing `HAS_YTSTACK`, `YT_DIR`, `CWD`. `init-project` additionally uses `_PROJECT_KEY` wherever it creates or names the user-scope dir (`~/.ytstack/projects/<key>`), and its `_IS_GIT` comes from the block. `summarize-task` drops its own `_IS_GIT=$([ -d .git ] ...)` line. Nothing else in the procedures changes in this task (commit discovery = T02, sentinels/gitignore = T03, handoff reading = T04).
