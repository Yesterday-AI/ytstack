# M031-S05-T01 -- Task Plan

## What this does

`scan` looks at a fixed list of directories relative to the repository root: `plans`, `plan`, `planning`, `roadmap`, `docs/plans`, `docs/plan`, `docs/planning`, `docs/roadmap`. It reads every `*.md` up to three levels deep in one `awk` pass and counts work rows:

- a task-list item (`- [ ]`, `- [x]`, also `*` and `+`);
- a data row of a Markdown table whose header names a status column (`Status`, `State`, `Done`, `Progress`, `Stand`, `Erledigt`) or whose first data row has a checkbox cell (`[ ]`, `[x]`).

Fenced code blocks are skipped. A row's state: `done` (`[x]`, or a status cell starting with done, merged, complete, shipped, closed, finished, landed, released, erledigt, fertig or a check mark), `dropped` (dropped, cancelled, superseded, obsolete, wontfix, skipped, abandoned), else `open`. A file is a plan file with at least 3 work rows. A directory is `large` when its plan files hold at least 10 open rows (`YTSTACK_PLAN_MIN_OPEN` overrides). The answer recorded in `PREFERENCES.md` (`external_plans: <dir> mapped|declined <date>`, one line per directory) is reported per directory.

Output: one line per directory with plan files, `dir=plans files=12 open=340 done=820 verdict=large answer=none`; `no external plan` when there is none. Exit 0 when at least one directory is `large` with `answer=none` (there is something to offer), 1 otherwise, 64 on usage.

`rows [--open] [PATH...]` prints one line per work row, tab separated: `path:line`, state, id (the `ID`-like column, else `-`), section (the nearest heading above), title (the deliverable-like column, else the first other cell, at most 100 characters). Without PATH: the plan files of every candidate directory. `-C DIR` like the other scripts.
