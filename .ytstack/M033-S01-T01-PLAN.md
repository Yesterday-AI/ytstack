## What this does

- `upstream_feedback: suggest | file | off` in `.ytstack/PREFERENCES.md` (frontmatter or body, `key: value` or `key=value`, like every key `yt_pref` reads). Without it, the last `upstream_feedback=` line of `~/.ytstack/config`. Without both, `suggest`. A value outside the three reads as `suggest` and adds a line to `YT_PREF_WARNINGS`: a typo never publishes.
- `ytstack-upstream [-C DIR] mode` prints `mode:` (effective), `set:` (value and where it came from), `gh:` and `repo: Yesterday-AI/ytstack`. Only for `file` it asks `gh auth status`; without `gh` or without a login the mode is `suggest` with a `note:` line. Exit 0; 64 on usage.
- `ytstack-upstream draft --kind bug|gap|proposal|evidence --title TEXT [--host NAME] [--out FILE]` writes an issue body with the sections "What happened", "Evidence", "Proposal", a footer with the ytstack version (from `.claude-plugin/plugin.json` next to the script), the host and the OS, and a `Searched:` line; every part the agent has to write is a `TODO:` line. Default path under `$TMPDIR`, never inside the checkout; an existing file is not overwritten. Prints the path and the title. Never calls `gh`.
- `ytstack-upstream check FILE` prints one line per problem and exits 1: a `TODO:` left, an empty "Evidence" section, no filled `Searched:` line, an email address (a `noreply` address excepted), a token-looking string (the rule of `bin/ytstack-handover`), a home directory path (`/Users/<name>/`, `/home/<name>/`). Exit 0 with `draft ok`.
