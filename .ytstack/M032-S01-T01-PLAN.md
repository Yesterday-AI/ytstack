# M032-S01-T01 -- Task Plan

**Summary:** `bin/ytstack-signals` records lessons as findings of `kind: lesson` with a class key, a count and a target, links them into incident records, lists them per window, and its check fails on a closed incident without a lesson and on a lesson without a valid target.

## Files

- Modify: `bin/ytstack-signals` (usage, `KINDS`, `AREAS`, `TTYPES`, helpers `slug`, `lesson_key`, `target_ok`, `target_path`, `rows` with the target column, `cmd_new --target`, `cmd_set --target`, incident skeleton `lesson: none`, `lesson new`, `lesson list`, `check_findings`, `check_incidents`)
- Modify: `tests/ytstack-signals.test.sh` (the incident skeleton and closed records, a section `# lesson`, incident lesson defects)

## What this does

- `lesson new --area <production|ci|evidence|review|process> --class <slug> --title <text> --target <type>:<where> [--incident <id>] [--read-at <time>] < what happened` records through `new`: key `lesson:<area>:<class>`, source the area, `target:` in the frontmatter. A repeat of the class is `seen-again` (count), a repeat after `fixed` a `regression`.
- `--target` takes `check:<path>`, `knowledge:<path>[#anchor]`, `contract:<path>[#anchor]` or `proposal:<ref>`; `AGENTS.md` and `CLAUDE.md` are refused (exit 64).
- `--incident <id>` writes the lesson id into the record's `lesson:` line (comma separated, `none` replaced, a missing line added).
- `lesson list [--state] [--since <UTC>]`: id, state, area, class, count, sightings since, target, ref, reopens, title.
- `set <id> --target` (lessons only); `set --state fixed` refuses a proposal target and a target file that does not exist.
- `check`: a lesson's key, source and target form, `AGENTS.md`/`CLAUDE.md`, a fixed lesson's target; an incident record's `lesson` form, a closed record with `lesson: none` (or no line), an id that is no lesson.
