## What this does

`resume-session` preamble (lib loaded): `_LATEST_LINK="$(yt_state_base)/repos/$YT_REPO_KEY/worktrees/$YT_WT_KEY/latest-handoff"`; if it resolves, `_LATEST_AUTO_HANDOFF=$(readlink ...)`, `_AUTO_HANDOFF_TS` from its `timestamp:`; `_MANUAL_HANDOFF_EVENT` / `_MANUAL_HANDOFF_TS` from `.ytstack/HANDOFF.md` when present. Echo all four (or `none`). Procedure step 2 ("Read HANDOFF.md if present") becomes "Read handoffs": read the automatic one when present (it is always the freshest breadcrumb of *this* worktree), then the manual one, and open the briefing with one line: "Handoffs: automatic <ts> (<path>), manual <event> <ts>" so the user sees which source the briefing leans on; if the manual handoff is newer than the automatic one, lean on the manual one.

`handoff-session`: the written `HANDOFF.md` keeps `event: user-triggered`; add a frontmatter comment line `# user-owned: hooks never write this file (automatic handoffs live out of tree)` and a sentence in the report pointing at `resume-session`.

Test: in `tests/skill-preambles.test.sh`, before the loop run `hooks/pre-compact` once for the main fixture (payload cwd = MAIN, `CLAUDE_PLUGIN_DATA` = fixture data dir) and pass `CLAUDE_PLUGIN_DATA` into `run_pre`; for `resume-session` assert the output contains `LATEST_AUTO_HANDOFF: <data>/repos/` and `MANUAL_HANDOFF_EVENT: user-triggered` (fixture gets a manual HANDOFF.md). Worktree run: `LATEST_AUTO_HANDOFF: none` (no pre-compact ran there).
